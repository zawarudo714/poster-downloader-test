v143 — two names a rule cannot rebuild, and the number column

The titles table held one name. A title is three in practice: what the
worker reads, what gets searched for, and what the marketplace lists. The
movie niche could derive the last two, travel cannot — "Niagara Falls"
searches as "Niagara Falls USA" and "Taj Mahal" as "Taj Mahal Agra India",
decided by different rules across the whole catalogue, so no pattern
reproduces both.

* Two nullable columns on master_titles: `search_query` and
  `marketplace_title`, plus their entries in NEW_COLUMNS.
* `listing_name()` and `search_text()` in pipeline.py — ONE place each for
  the fallback, so two callers cannot disagree about it. Both fall back to
  the plain title, which is what keeps every existing sheet importing and
  behaving exactly as before.
* The importer reads the two new columns; absent columns leave them NULL.
* The in-page search now searches `search_text(t)`, not `t.title`.
* `{title}` in the marketplace template now renders the listing name.
* APP_VERSION 143. The previous deploy shipped as a second v142 against a
  different commit, which the deploy tool warned about at the time.
* Removed from the repo: the LibreOffice lock file. `.gitignore` now covers
  those and the catalogue CSV — 21 MB of DATA that was going into every
  Docker image as a second copy of a file that lives one folder up.
  travel_titled.csv itself still needs deleting by hand; the mount would
  not let me.

INVARIANT ADDED, as the standing rule requires
  `check_sheet_columns_all_or_nothing` — within one project the two new
  columns are on every title or on none. Both are optional and both fall
  back silently, which is exactly what makes a lost column invisible: a
  renamed header and every title quietly searches on the bare name and
  lists under the wrong one, with no error anywhere. A half-filled project
  is the only sign, so that is what is watched.

  SABOTAGE-TESTED ONLY IN PART. The decision was exercised against the
  shipped source and fires on a partial fill and nowhere else. The QUERY
  was not — it needs sqlalchemy and this machine has none.
  `tools/test_sheet_columns_check.py` runs the rest against a throwaway
  database:

      docker compose exec web python tools/test_sheet_columns_check.py

  Run it before believing the check. Its first version pointed at DB_PATH,
  which is derived rather than read, so it would have run against the live
  catalogue — its own guard caught that.
